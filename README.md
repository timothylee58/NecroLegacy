# NecroLegacy

NecroLegacy is a digital autopsy workbench for legacy data. It takes a fixed-width or COBOL batch dump, a copybook, or a photo of a printed table. A five-node LangGraph pipeline then infers the schema, scores statistical outliers, explains the rot and generates a FastAPI wrapper. Results appear in a Three.js "Autopsy Table", a Vision X-Ray overlay for scanned images, and a Kiro MCP server.

Built for Kiroween 2026: Build with Kiro

Pipeline order: `vision_extractor` (images only), `schema_archaeologist`, `ml_rot_scorer`, `rot_detector`, `api_resurrector`. Deterministic checks and the Isolation Forest run before any LLM call. LLMs explain findings and never compute scores.

## Repository layout

| Path | Contents |
|---|---|
| `apps/web` | Next.js 15 workbench (React 19, Tailwind, shadcn/ui, Framer Motion, Three.js) |
| `apps/api` | FastAPI service, LangGraph pipeline, OpenCV and scikit-learn services |
| `packages/mcp-server` | Kiro MCP server (`inspect_legacy_schema`, `query_rot_anomalies`) |
| `sample-dumps` | Three synthetic presets, generated by `scripts/generate_presets.py` |
| `scripts` | Preset generator and repository checks |
| `.kiro` | Steering files and the spec (requirements, design, tasks) |

## Run locally

Requirements: Node 20+, pnpm 10, Python 3.12.

```bash
pnpm install

# Web app on typed mock data, no backend needed
cd apps/web && NEXT_PUBLIC_USE_MOCK=true pnpm dev

# API (needs Redis and Postgres with pgvector; docker compose provides both)
cp .env.example .env   # fill in WEB_ORIGIN, REDIS_URL, DATABASE_URL
docker compose up --build

# Web app against the API
cd apps/web && NEXT_PUBLIC_API_URL=http://localhost:8000 pnpm dev
```

Python development setup:

```bash
cd apps/api
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
.venv/bin/pytest
```

Tests never call a real LLM, Supabase or Redis. They use `respx`, `fakeredis` and stubs.

## Environment variables

The free deployment runs the web app as a Render static site (`render.yaml`) and the API on Google Cloud Run, with Neon for Postgres + pgvector, Upstash for Redis and AxForge for the LLM. Step-by-step setup, the reasoning behind each setting and a cost breakdown are in [docs/deploy-cloud-run.md](docs/deploy-cloud-run.md); `.github/workflows/deploy-api.yml` redeploys the API after CI passes on `main`. The API is a plain container (root `Dockerfile`), so any host with about 2 GB of memory and a single instance works. Never commit values; `.env` is git-ignored.

`NEXT_PUBLIC_*` values are baked in at build time, so redeploy the site after changing them.

| Name | Purpose | Render | API host |
|---|---|---|---|
| `WEB_ORIGIN` | Browser origin allowed by CORS (single origin, no wildcard) | - | required |
| `REDIS_URL` | Redis connection URL for the result cache | - | required |
| `DATABASE_URL` | Postgres with pgvector for record search. Use the **direct** (non-pooled) string, Neon's `DATABASE_URL_UNPOOLED`. `SUPABASE_DB_URL` is accepted as an alias | - | required |
| `LLM_PROVIDER` | `bedrock` (default) or `openai_compatible`; the free deployment uses `openai_compatible` with AxForge | - | optional |
| `LLM_PRIMARY_MODEL` | Primary open-weight model id (default `openai.gpt-oss-120b-1:0`; `qwen3.8-flash-next` on AxForge) | - | optional |
| `LLM_PRIMARY_VISION` | `true` if the primary model accepts images (default false) | - | optional |
| `LLM_FALLBACK_MODEL` | Fallback model id, Claude on Bedrock by default; `qwen3.8-27b` on AxForge | - | optional |
| `LLM_PRIMARY_REASONING_EFFORT` | `none`, `low`, `medium` or `high`, sent as `reasoning_effort` to the primary on `openai_compatible` only when set. gpt-oss accepts only low/medium/high | - | optional |
| `LLM_FALLBACK_REASONING_EFFORT` | Same for the fallback. Leave both unset on AxForge, which rejects unknown request fields; its Qwen models answer without thinking by default | - | optional |
| `LLM_FALLBACK_VISION` | `true` if the fallback model accepts images (default true) | - | optional |
| `AWS_REGION` | Bedrock region | - | optional |
| `AWS_ACCESS_KEY_ID` | Bedrock credential; leave unset when using an IAM role | - | optional |
| `AWS_SECRET_ACCESS_KEY` | Bedrock credential; leave unset when using an IAM role | - | optional |
| `AWS_SESSION_TOKEN` | Temporary Bedrock credential | - | optional |
| `LLM_BASE_URL` | Base URL of an OpenAI-compatible endpoint (`openai_compatible` only) | - | optional |
| `LLM_API_KEY` | API key for the OpenAI-compatible endpoint | - | optional |
| `OCR_ENGINE` | `tesseract` or `paddleocr`. The Docker image sets `tesseract` and installs PaddleOCR (`apps/api/requirements-paddle.txt`) only when built with `--build-arg WITH_PADDLE=1` | - | optional |
| `EMBEDDING_PROVIDER` | `hash` (default, local) or `api`. `api` sends record text to a third party | - | optional |
| `EMBEDDING_API_URL` | Embedding endpoint, used when `EMBEDDING_PROVIDER=api` | - | optional |
| `EMBEDDING_API_KEY` | Embedding endpoint key | - | optional |
| `EMBEDDING_MODEL` | Embedding model name | - | optional |
| `CACHE_TTL_SECONDS` | Cache lifetime, 60 to 604800 (default 86400) | - | optional |
| `SANITIZER_MAX_CHARS` | Maximum characters per value sent to an LLM, 1 to 100000 (default 10000) | - | optional |
| `MAX_CONCURRENT_SESSIONS` | Parallel pipeline runs, 1 to 8 (default 2) | - | optional |
| `RATE_LIMIT_SESSIONS_PER_HOUR` | New sessions (uploads and presets) per client per hour, 1 to 10000 (default 30) | - | optional |
| `RATE_LIMIT_SEARCHES_PER_MINUTE` | Searches per client per minute, 1 to 10000 (default 30) | - | optional |
| `CLIENT_IP_HEADER` | Header that carries the client address; the last comma-separated entry is used, because edges append it after anything the caller sent. `x-forwarded-for` on Cloud Run, `x-real-ip` on Railway. Unset, all callers share the proxy's limit | - | recommended |
| `API_TOKEN` | When set, the API rejects requests that send a different bearer token. Requests with no `Authorization` header are still accepted, so this is not access control; the rate limits are | - | optional |
| `LOG_LEVEL` | Log level (default `INFO`) | - | optional |
| `NEXT_PUBLIC_API_URL` | API base URL used by the web app, read at build time | required unless mock | - |
| `NEXT_PUBLIC_USE_MOCK` | `true` runs the web app on built-in mock data. Leave unset in production | optional | - |
| `NECRO_API_URL` | API base URL used by the MCP server | - | - |
| `NECRO_API_TOKEN` | Bearer token the MCP server sends (must match `API_TOKEN`) | - | - |
| `MCP_ANALYSIS_TIMEOUT_MS` | MCP wait for an analysis, default 300000 | - | - |

`NECRO_API_URL`, `NECRO_API_TOKEN` and `MCP_ANALYSIS_TIMEOUT_MS` belong to the MCP server process on the developer machine, not to Render or the API host.

## Kiro MCP server

Build it, then register it in `.kiro/settings/mcp.json`:

```bash
pnpm --filter @necrolegacy/mcp-server build
```

```json
{
  "mcpServers": {
    "necrolegacy": {
      "command": "node",
      "args": ["packages/mcp-server/dist/index.js"],
      "env": {
        "NECRO_API_URL": "http://localhost:8000",
        "NECRO_API_TOKEN": "<same value as API_TOKEN>"
      }
    }
  }
}
```

Tools:

- `inspect_legacy_schema` takes `file_path` (optionally with `copybook_path`) or a `preset` name and returns the inferred schema and anomaly counts.
- `query_rot_anomalies` takes a `session_id` with optional `severity` and `entity` filters.

## Sample data

All presets in `sample-dumps` are synthetic. They contain no real names, emails, phone numbers, government IDs or account numbers. `scripts/check_presets.py` enforces this in CI.
